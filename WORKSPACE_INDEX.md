# WORKSPACE_INDEX.md — Единая карта проектов

Этот файл — главная точка входа в рабочие материалы аккаунта GitHub `balalau1987`.
Он связывает репозитории, но не смешивает исходный код разных проектов.

## Репозитории

### 1. Работа Всем — основной продукт
- Репозиторий: https://github.com/balalau1987/rabota-cheboksary
- Назначение: сайт rabotavsem.top, WordPress, личный кабинет, заявки, чат, ИИ-помощник, MAX Bot.
- Начинать изучение с:
  1. `PROJECT_STATE.md` — текущее состояние и правила работы.
  2. `CLAUDE.md` — локальные инструкции разработчика и деплоя.
  3. `docs/PLAN.md` — план MAX Bot и связанные решения.
- Код сайта находится в `wp-content/`.
- Не считать пункты плана реализованными без проверки кода и теста.

### 2. first-project — общие инструменты и навыки разработки
- Репозиторий: https://github.com/balalau1987/first-project
- Назначение: навыки Claude Code, справочники инструментов, шаблонная страница и списки задач.
- Начинать изучение с:
  1. `CLAUDE.md` — правила работы с задачами и навыками.
  2. `tools.md` — каталог источников и установленных навыков.
  3. `tasks/personal.md` и `tasks/work.md` — раздельные списки задач.
  4. `.claude/skills/` — локально доступные Claude Code skills.
- Этот репозиторий не является исходным кодом сайта rabotavsem.top.

Если задача относится к конкретному другому продукту, не складывать его код в репозиторий Работа Всем. Сначала определить отдельный репозиторий или папку проекта.

## Общие правила для ChatGPT и Claude Code

1. Перед работой определить репозиторий по задаче.
2. Прочитать этот индекс и локальный `CLAUDE.md` соответствующего репозитория.
3. Проверить актуальные файлы и последние коммиты; не полагаться только на старые заметки.
4. Разделять факты, планы и предположения. Отмечать непроверенные функции как непроверенные.
5. Не переносить и не переименовывать существующие папки без необходимости.
6. Не хранить секреты, токены, пароли, персональные данные пользователей и дампы баз в Git.
7. Не публиковать изменения на рабочем сайте без отдельного согласия владельца на конкретный деплой.
8. После существенной работы обновлять соответствующий файл состояния и журнал изменений.
